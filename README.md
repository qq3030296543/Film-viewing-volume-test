# 光影鉴赏局

> 一帧光影，照见你的阅片阅历。看过不算，记得才算。

**光影鉴赏局**是一款通过电影海报与代表性画面猜片名的阅片测试网站。无需注册，选择题量、电影类型和影迷身份即可开始；完成测试后，系统会根据正确率、连续答对次数与类型表现生成专属阅片段位。

[立即开始测试](https://film-viewing-volume-test.netlify.app/)

## 怎么玩

1. 选择测试长度：快速测试 10 部、标准测试 20 部或深度测试 30 部。
2. 选择电影类型：综合、华语、欧美、日韩、动画、科幻、悬疑、恐怖、喜剧或文艺经典。
3. 选择自认为最符合自己的影迷身份。
4. 根据隐藏片名的电影海报或剧照，从四个片名中选出正确答案。
5. 作答后可以直接打开该电影的 TMDB 资料页，继续了解影片信息。
6. 完成全部题目，查看总分、正确率、类型表现与最终阅片段位。

答题时可以使用鼠标、触摸屏或数字键 `1`～`4` 选择答案；也可以随时返回首页、重新测试或恢复尚未完成的测试。

## 三种影迷身份

| 身份 | 适合谁 | 选片特点 |
| --- | --- | --- |
| 入门菜鸟 | 刚开始系统看电影，或想轻松热身 | 以知名度较高、观众基础较大的电影为主 |
| 略知一二 | 有一定阅片量，希望遇到更有迷惑性的题目 | 扩大地区、年代和类型范围，干扰片名更加相近 |
| 阅片无数 | 熟悉主流佳作，也接触过不同电影传统 | 放眼整个电影史，在保证基本口碑与观众样本的前提下拓宽选片 |

难度并不依靠低分电影、极冷门影片或明显无关的错误选项制造。系统会优先从相近地区、年代、类型、热度和片名特征的电影中生成干扰项，让判断更多依赖真实的电影记忆。

## 题库与防重复机制

- 在线版本通过 TMDB 实时获取电影资料，不局限于固定的本地片单。
- 每次测试会根据所选类型和身份，从不同数据页随机建立候选池。
- 浏览器会保存该设备上所有已经出过的 TMDB 电影 ID，新测试优先选择从未出现过的电影。
- 浏览器会按电影和挑战身份记录作答次数、正确次数及常见误选项，为后续难度校准提供真实的本机样本。
- 防重复记录仅表示“是否曾经在测试中出现”，与电影上映时间无关；选片范围覆盖整个电影发展历史。
- 系统排除纪录片、电视电影、演唱会、巡演和音乐现场等非正式叙事电影，同时保留具有完整故事的音乐电影。
- 电影图片会准备多条备用地址；加载失败时会自动切换，避免出现空白题目。

如果在线数据库暂时不可用，网站会自动切换到内置本地题库，测试流程仍可正常完成。

## 成绩与阅片段位

选对电影名称即算答对，不再追加第二道剧情验证题。最终成绩按照正确题数换算为百分制，并展示：

- 正确数量与总体正确率；
- 最高连续答对次数；
- 不同电影类型的表现；
- 分类能力雷达图；
- 专属阅片段位与评价；
- 推荐继续观看的电影；
- 适合保存或截图的分享卡片。

测试结果不会公开题目答案。当前进度、历史成绩、最佳成绩和防重复记录保存在当前浏览器中。

不同影迷身份使用独立的段位阈值，因此不同难度下的同一分数不会被解释为完全相同的水平。结果页只展示当前身份内的表现评价与本机历史样本，不使用没有真实数据支持的“超越多少玩家”模拟百分位。

## 隐私说明

网站不要求注册、登录或提交个人资料。答题进度、成绩与已出现电影记录使用浏览器 `localStorage` 保存，不会由本项目主动上传到服务器。清除浏览器站点数据后，这些本地记录也会被清除。

## 本地运行

需要安装 Node.js 20.19+ 或 22.12+。

```bash
npm install
npm run dev
```

生产构建与预览：

```bash
npm run typecheck
npm run build
npm run preview
```

项目使用 React、TypeScript 与 Vite 构建，不需要登录、支付或独立业务后端。

## 添加本地电影

在 `src/data/movies.ts` 的 `movieSeed` 数组中新增符合 `Movie` 类型的数据，类型定义位于 `src/types.ts`。对应海报放入：

```text
public/posters/电影ID.jpg
```

识别测试主要使用以下内容：

- 中文名、英文名、年份、地区、类型、导演与简介；
- 海报地址、图片替代文本和占位视觉颜色；
- 三个片名干扰选项；
- 难度与推荐理由。

数据结构中保留的内容验证字段仅用于兼容旧题库，当前单阶段答题流程不会显示第二道内容题。

## TMDB 数据配置

在线生产版本通过 `netlify/functions/tmdb.mts` 在服务端代理 TMDB 请求。普通访客不需要填写 API Key，生产密钥也不会进入浏览器或公开源码。

Netlify 部署时，在项目的 Environment Variables 中添加：

```env
TMDB_API_KEY=你的_v3_API_Key
```

保存后重新部署。变量不要添加 `VITE_` 前缀，否则会被前端构建工具视为可公开读取的变量。

本地开发可以复制 `.env.example` 为 `.env.local`：

```env
VITE_TMDB_API_KEY=你的_v3_API_Key
```

`.env.local` 已被 Git 忽略，不要将真实密钥提交到公开仓库。部署到其他平台时，需要提供与 `/api/tmdb/*` 等价的服务端代理。

## 数据来源

本产品使用 TMDB API，但不受 TMDB 认可或认证。电影资料和图片的使用遵循 TMDB API 的相关条款。
